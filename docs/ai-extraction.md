# AI claim extraction contract

`app.ai.extraction.ClaimExtraction` is a Pydantic contract separate from the database claim model. It contains the incident type, incident date, policy number, damaged parts, repair estimate, currency and uncertainties. Each scalar is required in the response but may be `null`; lists must be present and may be empty. Repair estimates use nonnegative decimal strings in model responses and can be accessed as a Python `Decimal` for calculations. Currency must be an uppercase ISO 4217 code. Dates must be ISO calendar dates.

`missing_fields(extraction, has_verified_policy=False)` checks incident type, incident date and policy reference in Python. Passing `has_verified_policy=True` means a trusted policy association already exists, so the reference need not appear in the description. Missing fields and model-reported uncertainties remain separate.

The contract validates shape, not truth. The shared provider instructions treat claim descriptions as untrusted, require unsupported or contradictory facts to remain uncertain, and prohibit coverage decisions and claim approval or rejection. A valid response still needs factual evaluation. The OpenAI and Gemini adapters request structured output without automatic retries. Gemini free-tier content may be used to improve Google products; use synthetic claims and verify the project billing tier before testing. The claim service validates the result and persists a new analysis; it does not change the claim. The CLI also supports text-only extraction without a claim record. Because policy links do not yet have a verification state, the database-backed workflow does not treat a link as verified for completeness.
